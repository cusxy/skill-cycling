# AGLOOM.md

Этот файл — канонический контекст плагина для AI coding-агентов. Agloom транспилирует его в `CLAUDE.md`, `AGENTS.md` и аналоги при установке плагина в consumer-проект.

## Что это

`skill-cycling` — плагин для хост-инструмента **Agloom**. Репозиторий содержит только markdown-инструкции и YAML-схемы. Артефакты плагина устанавливаются в consumer-проект и потребляются AI-агентами (Claude Code, opencode) как системные промпты и справочники.

Манифест плагина: `plugin.yml`.

## Команды

| Команда                 | Назначение                                                          |
| ----------------------- | ------------------------------------------------------------------- |
| `agloom format`         | Форматирует markdown-документы плагина (front matter, prose, схемы) |
| `agloom format --check` | Валидирует форматирование и линтит markdown без изменения файлов    |

Хост-инструмент `agloom` — единственный источник валидации в этом репозитории: собственного build/test-пайплайна нет. Запускай `agloom format --check` перед коммитом и `agloom format` для авто-исправлений.

## Архитектура

### Слои

| Директория             | Роль                                                                                                    |
| ---------------------- | ------------------------------------------------------------------------------------------------------- |
| `agents/`              | Определения субагентов (executor/reviewer) — по одному `.md` на агента, front matter + системный промпт |
| `skills/`              | Skill-оркестраторы (`SKILL.md` + опц. `manifest.md`, `docs/`). Один skill = один цикл                   |
| `docs/cycling/`        | Инвариантные протоколы: `orchestrator-protocol.md`, `agent-protocol.md` (+ design-версии)               |
| `docs/document-types/` | Описания типов документов (`index`, `spec`, `doc`, `research`, `agent`, `skill`, `manifest`)            |
| `schemas/draft/`       | YAML-схемы типов документов, валидируемые против `schemas/meta-schema.json`                             |
| `docs/*.md`            | Исследования и методологические документы (agent-as-program, SOP patterns, DoR/DoD и др.)               |

### Модель цикла (agent cycling)

Skill = оркестратор, работающий **inline** в основном контексте; он вызывает субагентов через Agent tool, но сам файлы проекта не правит. Цикл — последовательность фаз вида `executor → reviewer`. Переход дальше только при `verdict: pass`. Любой reviewer МОЖЕТ через `returnTo` отправить работу к более раннему executor; при возврате повторяется вся цепочка.

Каждый агент:

- запускается с **изолированным контекстом** (нет доступа к предыдущим фазам, всё через scope+context prompt);
- executor'ы могут быть **возобновлены** (resume) при возврате от своего reviewer — контекст сохраняется;
- выполняет свои DoR перед началом и DoD перед завершением (формат — см. `docs/cycling/agent-protocol.md`);
- агентам ЗАПРЕЩАЕТСЯ редактировать артефакты более ранних фаз — это сохраняет независимость ревью.

Текущие циклы плагина: `spec-cycle` (specify → test → implement, 6 агентов), `research-cycle`, `cycle-creator`.

При работе с любым агентом/оркестратором ТРЕБУЕТСЯ прочитать соответствующий протокол из `docs/cycling/` — это пререквизит, на который ссылаются все агенты.

## Конвенции

- **Язык прозы**: русский. Ключевые слова RFC 2119 (`ТРЕБУЕТСЯ`, `СЛЕДУЕТ`, `МОЖЕТ`, `ЗАПРЕЩАЕТСЯ`) — в обязательствах и запретах.
- **Front matter обязателен** во всех markdown-файлах под `docs/`, `skills/`, `agents/`. Тип документа определяется полем `blueprint` (путь к схеме) либо контекстом директории. Валидные типы: `index`, `spec`, `doc`, `research`, `agent`, `skill`, `manifest`, `agents-md`.
- **Интерполяция путей**: ссылки между файлами плагина используют `\${agloom:PROJECT_DIR}`, `\${agloom:DOCS_DIR}`, `\${agloom:AGENTS_DIR}`, `\${agloom:SKILLS_DIR}`. Хост-инструмент подставляет реальные пути при установке. Не заменяй их литералами.
- **Директивы платформ**: блоки `<!-- agent:claude --> … <!-- /agent:claude -->` и `<!-- agent:opencode --> … <!-- /agent:opencode -->` дают альтернативные версии одного раздела для разных CLI. Правь обе ветки синхронно.
- **Запрет редактирования артефактов ранних фаз** — см. архитектурный раздел выше. Если ошибка найдена в спецификации из фазы `implement`, оркестратор обязан вернуться к `spec-writer`, а не править спеку из кода.

## Документация

> Индекс ключевых документов плагина. Описания взяты из front matter. При написании или правке любого агента/скилла сверяйся с `agents-md-quality-criteria.md` (критерии I1–I5) и соответствующей схемой из `schemas/draft/`.

### Протоколы цикла

- [orchestrator-protocol.md](docs/cycling/orchestrator-protocol.md): инвариантные механизмы запуска, мониторинга, возобновления агентов и обработки результатов.
- [agent-protocol.md](docs/cycling/agent-protocol.md): runtime-протокол для агентов агентных циклов — формат ввода/вывода, findings, DoR/DoD.
- [cycle-design-protocol.md](docs/cycling/cycle-design-protocol.md): design-time протокол — RFC 2119, тон и стиль, общие правила написания определений агентов и skill-оркестраторов.
- [agent-design-protocol.md](docs/cycling/agent-design-protocol.md): design-time протокол — структура определений агентов, критерии проверки, валидация системы.
- [orchestrator-design-protocol.md](docs/cycling/orchestrator-design-protocol.md): design-time протокол — структура SKILL.md, формат фаз, связь skill с агентами.

- [document-meta-schema.md](docs/document-meta-schema.md): проектирование мета-схемы для типизации и валидации markdown-документов, анализ `$schema` и `blueprint`, версионирование, каналы стабильности.
- [ai-markdown-review-prompts.md](docs/ai-markdown-review-prompts.md): тир-система актуальных техник промпт-инжиниринга для задач автоматизированного ревью документации.
- [validated-level-plan.md](docs/validated-level-plan.md): подробный план с шагами по переходу системы spec-cycle от уровня Structured к уровню Validated.

## Границы

- ЗАПРЕЩАЕТСЯ заменять интерполяционные переменные `\${agloom:*}` литеральными путями — плагин перестанет собираться для consumer-проектов с нестандартной раскладкой.
- ЗАПРЕЩАЕТСЯ добавлять прозу, дублирующую информацию, которую агент получает из кода/схем (критерий I1) — по эмпирическим данным это ухудшает compliance сильнее, чем отсутствие инструкции.
- ЗАПРЕЩАЕТСЯ превышать 200 строк в файлах типа `agents-md` и 500 строк в агентских промптах — зона деградации compliance (ETH Zurich, Instruction Gap).
- ЗАПРЕЩАЕТСЯ смешивать обязанности executor и reviewer в одном агенте — разделение фаз обеспечивает независимость ревью.
- ЗАПРЕЩАЕТСЯ редактировать файлы под `.idea/` — это локальные настройки IDE, не артефакт плагина.
